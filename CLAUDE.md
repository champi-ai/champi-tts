# CLAUDE.md

Project guidance for contributors and agentic tooling working in `champi-tts`.

## Stack

- Python `>=3.12` (CI tests 3.12 and 3.13), packaged with `hatchling`, managed with `uv`.
- Lint/format: `ruff`. Type-check: `mypy`. Tests: `pytest` + `pytest-asyncio` + `pytest-cov`.
- Optional extras: `kokoro` (torch-based provider), `ui`, `cli`, `web`, `pdf`, `mcp`, `all`, `dev`, `test`, `docs`.
- Entry points: `champi-tts` (`champi_tts.cli:main`), `champi-tts-mcp` (`champi_tts.mcp.server:main`).

## Setup

```bash
uv sync --all-extras --dev      # everything CI uses (includes the dev and test extras)
uv sync --extra docs            # docs-only environment
```

If the `kokoro` extra fails to resolve on Python 3.13, use `uv sync --python 3.12 --all-extras --dev`.

## Dev commands

These mirror `.github/workflows/ci.yml` and `pre-commit.yml`:

```bash
uv run ruff check .             # lint
uv run ruff format .            # format (CI runs: uv run ruff format --check .)
uv run mypy src                 # type-check
uv run pre-commit run --all-files
uv run mkdocs serve             # local docs preview (deployed via docs.yml with mkdocs gh-deploy)
```

## Tests and coverage

```bash
uv run pytest                   # full suite with coverage
uv run pytest tests/test_mcp -q # a single package
uv run pytest --no-cov -k name  # quick iteration without the coverage gate
```

- `[tool.pytest.ini_options]` adds `--cov=src/champi_tts --cov-fail-under=43`, so a plain `uv run pytest`
  fails below 43% total coverage. Running a subset of tests will trip this gate; use `--no-cov` for that.
- `[tool.coverage.report]` sets `fail_under = 40` for `coverage report`. Kokoro inference/models/provider
  need a GPU, so these floors are the realistic CI level, not a target.
- `kokoro/cli/*`, `cli/main.py`, `tests/` and `examples/` are omitted from coverage.
- Models, CUDA and audio devices are mocked, so no GPU is needed. `tests/test_providers/` still imports
  `torch`/`inflect`, so install the `kokoro` extra (part of `--all-extras`) to run the whole suite.
- Benchmarks (as run by `benchmarks.yml`):

  ```bash
  uv run pytest benchmarks/ --benchmark-only --no-cov
  ```

## Commits and releases

- Conventional commits, parsed by commitizen (`cz_conventional_commits`) to decide the bump. Use `uv run cz commit`
  or write `type(scope): description` by hand: `fix:` → patch, `feat:` → minor,
  `BREAKING CHANGE:` in the body → major; `chore:`, `docs:`, `test:`, `ci:`, `refactor:` → no bump.
- Releases are automated by `.github/workflows/release.yml` on every push to `main`: it runs
  `cz bump`, updates `CHANGELOG.md`, commits `bump: version X → Y`, tags `vX.Y.Z` (`tag_format = "v$version"`),
  builds with `uv build`, and creates a GitHub Release. It can also be triggered manually with a
  forced `patch`/`minor`/`major` bump or a dry run.
- Do not bump versions by hand. If you must, `uv run cz bump` keeps both version files in sync:
  `pyproject.toml` (`version`) and `src/champi_tts/__init__.py` (`__version__`).

## Project layout

- `src/champi_tts/` — package: `core/` (base provider/config/audio), `providers/kokoro/` (Kokoro provider),
  `reader/` (text/file reading service), `ui/` (ImGui indicator), `cli/`, `mcp/` (MCP server), `factory.py`.
- `tests/` — pytest suite, mirroring the package (`test_core/`, `test_providers/`, `test_reader/`,
  `test_ui/`, `test_mcp/`, `test_integration/`).
- `benchmarks/` — `pytest-benchmark` suites (`bench_*.py`).
- `docs/` — MkDocs sources (`mkdocs.yml` at the root).
- `examples/` — runnable usage examples.
- `scripts/` — maintenance scripts.

## House rules

- Never commit directly to `main`. Always work on a branch and open a pull request.
- Commit messages, PR titles and PR descriptions must not contain AI attribution: no `Co-Authored-By`
  trailers, no "generated by" footers, no mention of AI assistants.
- Run lint, format check, mypy and tests before pushing; CI runs the same commands.
